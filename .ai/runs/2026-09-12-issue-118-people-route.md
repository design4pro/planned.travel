## Goal

Ship `/trips/$tripId/people`: the members list, the invite control and the workspace-visibility
switch, reached from the sub-navigation's Share button — over the guards Phase 1 put inside the
writers, so the route contributes a tenant scope, a Zod boundary and a payload shape and makes no
authorisation decision of its own.

## Risks

- **This phase is stacked on an unmerged Phase 1.** The branch is cut from
  `feat/issue-118-membership-guards`. Once #453 merges it is rebased onto the base branch so the
  pull request carries only Steps 9-13.
- **The client graph.** `people.ts` is a route `-server` module, so anything it _exports_ must be
  resolvable in the browser bundle (the spec's `## Amendment`). `enqueueTripStatsFor` is reached only
  from handler bodies, and the queue binding behind it is a dynamic import, so nothing static crosses.
- **Thirty-three keys in twenty-three locales.** The parity test is the gate; the `i18n-messages`
  skill is the procedure.
- **The screen is the first surface for the Phase 1 refusals.** The two reasons cross the wire as a
  closed code vocabulary; a third would render as the generic failure and go unnoticed, so the
  mapping is asserted rather than assumed.
