## TLDR

Plan stage 13-S3 in `docs/plans/13-community-gallery.md` will let a visitor browse reviewed publications and read their day-by-day itineraries without an account. The proposed `/gallery` and `/gallery/$slug` routes serve approved immutable KV content after checking current publication authority in D1. A withdrawal therefore prevents subsequent authorized reads even while old KV documents remain.

## Current evidence and scope

No Gallery routes, community repositories, read-model or release handlers exist under `src/` at this revision. The approved [13-S1 publication-pipeline specification](2026-11-04-the-publication-pipeline.md), Spec PR #1846, is a dependency, not implemented code. Stage 13-S2 now has a ready [curation specification](2026-11-06-curation-review-and-release.md), Spec PR #1865, but no implementation. The S3 consumer contract below remains an explicit integration prerequisite for S2. The plan's assumed schema, release writer and KV contracts cannot be treated as existing primitives.

The marketing chrome, all 23 `marketing.ts` catalogues, map primitives and `src/server/public/rate-limit.ts` already exist. Reuse them. No new dependency, binding, D1 table, column, queue kind, quota metric, realtime event or photo pipeline belongs to S3. Activation and recovery reuse S2's deployment capability and bounded durable dispatcher.

The complete capability is anonymous discovery and reading: newest-publication hero, searchable remaining cards, complete itinerary, interactive map and original deterministic route art, linked from public chrome. Suggestions, comments reads and their empty placeholder, saved trips, copying into a workspace, curation and unpublished previews belong to other stages. An empty route alone does not deliver S3.

Reference check: `wiki: Plugins` was fetched during planning, together with the public demo entry and repository overview. The current documentation describes plugin surfaces but does not establish the plan's specific Gallery behavior. This design treats that behavior as our plan's requirement; it makes no claim of fresh visual comparison or reference feature parity. No reference code, copy or assets are incorporated.

## Dependencies and activation gate

S1 and S2 must be implemented and deployed before public routes or navigation activate. Pure art/UI tests can precede them; dependent tickets carry explicit blocking edges rather than inventing a release subsystem. S2 owns curation, immutable approved versions, release/retraction, recovery and all approval-side writes. It must provide this exact consumer contract before the reader integrates:

1. Stable unique slugs and globally unique publication IDs; tenant-bound immutable versions; a current live-version pointer independent of the pending version. Reviewing an update preserves the previous approved content and metadata. Withdrawal/takedown disables public authority, and source deletion or workspace deletion/erasure also denies it.
2. Strictly validated versioned KV index/detail documents described below, derived only from the approved immutable version. No pending metadata or live-trip fallback. Internal identity fields and integrity hashes never authorize themselves.
3. An authoritative D1 mapping from publication ID and live version to SHA-256 digests of the canonical public card and detail bodies. These digests are computed from the exact approved projection and installed with the live-version transition, with tenant/source/deletion predicates. They are not accepted from a submitter or inferred from KV. S2 owns any generated additive schema needed for this mapping; S3 adds no migration to compensate for a missing prerequisite.
4. Release, update, withdrawal and deletion tests that show stale/out-of-order KV writes cannot re-enable old authority. Reject over-limit projections before advancing public authority; retain the prior approved version on a failed replacement, report the release failure and keep the work recoverable. Never silently truncate the index or mark a not-released version successfully published. Existing safe lifecycle/outbox machinery remains S1/S2's owner.

S3 adopts S2's immutable generation/detail keys, strict array index, primary D1 control selection and release revision protocol below, and tests them against the real release path. S2's shared read-model producer must additionally install the canonical digest/art projection specified here before this consumer activates; keep this explicit blocking edge on ticket 1. If implementation differs from this combined contract, reconcile it in a reviewed change before activation; do not create a compatibility bypass. Missing, old or invalid payloads must never authorize access. The future curation preview may link to a live public slug; previewing unpublished content remains authenticated and outside these routes.

`community-public.ts` exposes `resolveLiveGallerySlugUnscoped(db, slug)` and `findLiveGalleryVersionsUnscoped(db, candidates)`, each with a file-header FU-3 justification and sole production caller `src/server/public/gallery.ts`. The slug resolver returns only `{ publicationId, liveVersion, tripDigest }` for an eligible exact slug, never public content; the shared key helper derives its immutable detail key. It applies the same tenant/source/policy/deletion predicates as the final resolver. Both functions require explicit SPEC/ACCESS amendments. The candidate resolver remains the final disclosure gate after KV validation. It takes at most 40 distinct `{ publicationId, version }` pairs per call. Each statement binds at most 80 candidate values; any additional bound predicates must keep the total at or below 100. The candidate resolver returns only `{ publicationId, liveVersion, indexDigest, tripDigest }`. No organization ID, slug, title, attribution, date, R2 key, trip row or snapshot leaves this repository projection.

The query matches publication and immutable version through their organization keys, the source trip's organization, current live-version pointer and current public eligibility. It excludes withdrawn/taken-down publications, missing/deleted source trips and workspaces whose deletion/erasure has started. Pending review alone is not a refusal when a previous approved version is still live. This grants access only to the explicitly approved publication, never to the source trip's ordinary private data. No fabricated tenant actor, general cross-tenant content read or new global-catalogue exception is permitted.

D1 authority reads use primary semantics, without stale replicas or a positive decision cache. Use the ordinary non-session D1 binding for every authority statement so all chunks go to primary. A future Sessions API adapter must create a fresh `first-primary` session for each individual authority statement; a shared sequentially consistent session is insufficient because later queries can use replicas. Pin this actual adapter behavior with a routing assertion; local D1 alone cannot prove production replica freshness. Read KV and compute/validate digests before the final authority check, then serialize only approved matches. A request overlapping a withdrawal can pass its authority check before the withdrawal commits; content already returned, downloaded or displayed cannot be recalled. A check begun after the committed withdrawal must refuse it.

This intentionally replaces the plan's KV-only reader and its no-repository-import assertion. Content remains in KV; D1 supplies current authority only. The implementation must amend SPEC §5's “D1 is never in the critical path for anonymous marketing pages” to allow this Gallery gate, and document the FU-3 resolver/public projection in §§5–6. Grep that claim and `Gallery`, `gallery:v1`, `13-S3`, `Unscoped` across waiting specs, CONTEXT, docs and source comments, updating every normative duplicate. Historical plan wording remains identified here as superseded by this design and the approved S1 disclosure boundary.

## Public read-model and limits

`src/server/community/read-model.ts` defines one canonical encoding of each public body as a fixed-field-order UTF-8 JSON tuple with explicit nulls and preserved ordered arrays; both writer and reader use it with platform SHA-256. For each card or detail envelope the digest preimage is exactly the canonical UTF-8 encoding of `[schemaVersion, publicationId, version, body]`, where `body` is itself encoded as its fixed-field-order tuple. This binds the identity/version outside `body` as well as slug, art, metadata, ordering and date visibility. Writer/reader fixtures must prove that changing any element changes or invalidates the digest; never hash a subset that leaves displayed fields unbound. Digests are lowercase 64-character hex. Strict schemas reject unknown fields and invalid or non-finite numbers. No stored HTML/SVG, arbitrary URLs or executable category icon identifiers.

- `gallery:v1:index:<generation>`: S2's immutable **strict JSON array**, at most **1,000 entries and 1 MiB encoded UTF-8**, checked before JSON parsing and after schema validation. Schema version is in the key prefix, not an object wrapper. Read the opaque active generation, generation revision and current visibility revision from primary D1 through the catalog owner before fetching; never construct a fixed index key or choose a generation from KV. Each entry contains internal `publicationId`, `version` and `body`: `{ slug, title, summary, attribution, dayCount, placeCount, countryCodes, publishedAt, art }`. Metadata uses S1's 120/280/80-character bounds; `publishedAt` is a validated UTC instant. Order by publishedAt descending, then publication ID, exactly as S2. No duplicate IDs or slugs. S2 persists this exact canonical entry JSON (including art) before live installation, admits the prospective array using its transactionally checked UTF-8 BLOB lengths plus brackets/commas, and concatenates those bytes without reserialization. Canonical digest preimages below are separate from this stored array encoding; fixtures pin both.
- `gallery:v1:trip:<publicationId>:<version>:<digest>`: S2's immutable detail key, derived only from the primary-authoritative slug identity and shared key helper. Its strict envelope is `{ schemaVersion: 1, publicationId, version, digest, body }`, at most **1 MiB encoded UTF-8**. `digest` equals the D1 trip digest and hashes the identity-bound canonical body, never itself. The body contains the same approved public metadata plus S1's strict bounded snapshot, including ordered days/places, dates only when explicitly allowed, and the same art projection. S1's independent 512 KiB snapshot, 366-day and 1,000-place/assignment capture limits continue to apply. Counts are derived from this snapshot, never a live source trip. No private IDs or free-form source records are passed through.
- One shared read-model slug validator serves S2 minting and S3 input/schema validation. Preserve S2's lowercase ASCII-folded kebab title prefix (1–48 characters, fallback `trip`), a hyphen, and the **full unchanged 25-character publication ID** validated with `src/lib/ids.ts`'s `ID_PATTERN`. Total length is 27–74; parse the last 25 characters as the ID and the preceding separator/prefix, since the random ID tail may itself contain hyphens. Preserve uppercase/underscore in that opaque suffix; never lowercase the whole slug or shorten the ID. Updates keep the original slug. Cross-spec fixtures cover the maximum prefix, mixed-case/underscore/hyphen suffixes, fallback and duplicate-title identities.
- `art` is at most **32** numeric normalized points with an explicit segment-start flag, all within `[0,1]`. It is computed during release from approved coordinates, never fetched per card. Points may be omitted for decoration; the detail itinerary and map keep every approved located place. No coordinate precision beyond the approved snapshot is introduced. Zero/one-point, coincident-point and dateline cases must yield finite stable art without inventing a connected travel leg across a day boundary.

For deterministic art, normalize the complete ordered valid-coordinate set first (unwrap longitude using the existing map helpers so dateline neighbors remain neighbors); a zero-range dimension becomes `0.5`. For `N` points choose `B = min(N, 32)` indices `floor(i * (N - 1) / (B - 1))`; for `B = 1` choose the first, and for zero use the empty variant. Set `startsSegment` on the first selected point and whenever its original day differs from the previous selected point. Connect only same-day selected points. More than 32 days can yield isolated dots; never invent inter-day legs. The read-model helper owns this reduction and both detail and cards use it.

The authority mapping binds each complete body to its publication/version; canonical digest comparison also binds the slug and approved metadata. A body with another tenant's bytes, a changed title, a mismatched version or altered art fails integrity rather than displaying. Internal envelopes/digests are stripped before returning browser props. Detail place/row identities are local stable indices, not source database identifiers.

The caps are initial operational bounds, not a claim that the entire future Gallery fits forever. A release exceeding either index bound is refused visibly without partial publication. Paging/sharding is a later reviewed read-model evolution, before the bound is raised, with compatibility for existing routes. No per-card fetch and no silent partial search. At 1,000 candidates, 40-pair chunks require at most 25 candidate authority queries plus bounded control reads; the reader issues no global scan and no D1 content reads.

Provider facts checked on 2026-11-06: [D1 limits](https://developers.cloudflare.com/d1/platform/limits/) specify 100 bound parameters per statement and 50 queries per Free Worker invocation; [KV writes](https://developers.cloudflare.com/kv/api/write-key-value-pairs/) document a 25 MiB value limit and cross-location visibility delays. [D1 Sessions API](https://developers.cloudflare.com/d1/worker-api/d1-database/) documents that `first-primary` applies to the first query, with subsequent session queries permitted on replicas; non-session queries use primary. The deliberately smaller application bounds and fresh D1 gate are essential; KV rewrite ordering or a short TTL is not revocation.

## Server functions, caching and failures

Both GET functions validate inputs with Zod, including the no-input case as a strict empty object. Use only trusted server-side request headers for caller identity. `loadGalleryIndex({})` returns `{ items }`; `loadGalleryTrip({ slug })` trims and validates with the shared 27–74-character producer slug contract and returns the authorized public body or null. No session is read. Only a current, validated empty generation returns `{ items: [] }`; missing index/control or an authoritative detail identity with a missing KV object is unavailable. No matching live slug authority returns null, with the same gone face for unknown, unreleased and withdrawn slugs. Do not expose a reason, tenant ID or pending title.

Rate control runs before KV payload or D1 reads: extend the existing limiter's type with a distinct `gallery` budget shared by index/detail, **60 requests/minute/IP**, using trusted `CF-Connecting-IP`, with one shared `unknown` fallback. Never trust `X-Forwarded-For` or an input IP. Use the existing 120-second counter expiry and fixed-window retry calculation. Above the approximate budget return 429 with `Retry-After` and localized retry guidance. Preserve existing callers and fail-open counter-outage behavior. This is best-effort cost control, not an atomic token bucket, guaranteed cost cap or authorization mechanism. Payload KV errors, D1 authority errors and integrity failures still fail closed.

The browse reader requires generation revision equal to current visibility revision, reads the selected immutable array, validates/hashes it and checks candidate chunks. After all chunks, re-read primary control and require the same active generation and unchanged matching revisions before serializing anything. Missing/mismatched live candidates or changed control mean unavailable, never a filtered partial list. This closes between-chunk withdrawal races without stale replica authority. A digest mismatch is corruption and unavailable. A missing/expired index or revision mismatch requests one idempotent bounded rebuild intent through the catalog's S2 recovery API; the existing dispatcher performs rebuilding, never this request. Intent-write failure still returns sanitized unavailable. No tenant content crosses that control API.

Detail resolves live slug identity on primary, reads only its immutable key, validates the envelope/body/requested slug and digest, then checks that same identity again through the final primary candidate resolver. No live identity before or after the read means gone; a still-live identity with missing/malformed/corrupt KV is unavailable. Neither path reads D1/R2 content, inserts quota rows, calls `assertQuota`, sends a queue message or sends notifications. Ordinary successful anonymous GETs perform no writes; exceptional browse recovery only requests the bounded existing rebuild intent.

Use `Cache-Control: no-store` for HTML and RPC responses, errors and gone faces. Do not populate CDN/Cache API or service-worker storage with Gallery content. Route preload is disabled; configure route freshness/retention so entering or revalidating a Gallery route performs a new authority check rather than serving a previously loaded match. Verify default router/query behavior and browser back/forward in integration tests. No service-worker implementation was found under `src/` or `public/` during this review; if one lands before implementation, inspect its interception/cache exclusions as part of this gate. A live browser need not poll or blank an already displayed publication; local search changes only that already returned list. Navigating to another detail, retrying or re-entering the route checks again. SEO/head metadata is generic until the authorized loader result exists; no raw KV body reaches HTML, head, hydration, structured logs or error messages.

Invalid JSON/schema/size/digest or unavailable KV/D1 returns a sanitized 503 unavailable result, distinct from empty/gone, with a retry that reruns the guarded loader. Log bounded error codes without published free text, IPs, snapshots or storage keys. Missing index/control or a referenced immutable object during KV propagation is unavailable, never a false empty/gone result; retries and S2 durable rebuild recovery eventually restore approved data. Availability lag after publication is allowed; disclosure of stale withdrawn content on a new authorized read is not.

## UI/UX

Use existing `SkipToContent`, `MarketingHeader`, `MarketingFooter`, `SectionLabel`, `Card`, `Input`, `Button`, `Alert`, `Skeleton` and `EmptyState`. Both routes SSR all titles, facts and text. Reserve art/map dimensions to avoid shifts. Dates/counts use existing locale formatters; country names use the locale catalogue's existing country-name mechanism. Published free text remains the submitter's text, escaped as text, never automatically translated or rendered as markup. Category names come only from the approved snapshot; unknown category icons use a fixed safe fallback.

Browse shows the newest authorized entry as the hero and the rest once in a 1/2/3/4-column grid at 360px/sm/lg/2xl, within the existing content measure. The hero and each card are single real links with visible focus and descriptive text; do not nest buttons inside a card link. Search is a labelled, bounded 200-character client-side filter over title, summary, attribution and localized country names from **all authorized index entries**, including the hero. Normalize/case-fold consistently for the current locale. With a non-empty query, show matches once in the grid without the hero, a localized result count and a clear control. Search makes zero network requests and never fetches hidden entries.

Each cover is original decorative inline SVG: warm brand wash, day-count numeral and normalized route sketch. It carries `aria-hidden`, uses no external asset, and is not a geographic navigation promise. Draw line segments separately for each sampled day, with visible isolated points; identical trips produce identical art. A zero-data illustration is also the browse-empty illustration. Reuse current tokens; no new font, token or raster image generation is needed.

Detail shows title, attribution, publication date, counts and country chips, then complete ordered day sections and place names/category labels. With `showDates` false, no trip calendar date is present in DOM, hydration, art labels or response; use numbered days. The public publication instant/date `publishedAt` remains visible and is independent of this choice. Preserve days without places. Each coordinate-bearing place has a map marker; absent/partial coordinates never produce a pin or NaN. On desktop (`lg`), itinerary and sticky map share two columns; at 360px the fixed-ratio map band precedes the itinerary. RTL mirrors logical layout and directional affordances without reversing itinerary order.

Reuse `MapCanvas`, `FitBounds`, `MapAttribution`, `BasemapNotice` and `PlaceMarker`'s safe display contract, adapting only approved public fields. Repeated places across days have distinct local day/place keys. No private popover fields, edit controls, remote photo URLs or tenant module imports. Selecting a row moves to its pin; selecting a pin scrolls its corresponding row into view. Located rows use native buttons named with place and day number; non-located rows remain plain readable text. Selected row and pin expose `aria-current="location"`, with one current local day/place identity. Keyboard activation of a pin scrolls and focuses the corresponding row; row activation retains row focus. Pointer activation scrolls/selects without moving focus away from its control, and hover never changes keyboard focus. Names distinguish the same place on different days. Support every located place, coincident pins and large snapshots without inaccessible overlapping-only controls: the itinerary remains the complete keyboard alternative. Use existing clustering/roving-focus behavior where applicable. Handle antimeridian bounds and a single point with existing map helpers.

Map failure or unavailable WebGL renders a localized fallback without breaking itinerary reading. No coordinates replaces the map with the designed explanatory card; absent basemap uses existing `BasemapNotice`, not the no-coordinates face. Theme updates retain selection. Reduced motion uses existing camera-motion helpers to jump, and disables art drawing, card rise and stagger. Ordinary card enter/hover motion is transform/opacity, 220ms easing with at most eight 24ms stagger steps.

Without JavaScript, all approved text and navigation remain readable. Search and map selection are progressive enhancements, disabled/absent until hydration, with a `noscript` explanation; never display a dead working-looking control. Do not promise an interactive SSR map. Skeletons use reserved dimensions and no repeated announcements; initial successful SSR does not conceal content behind them.

Named states: browse empty, populated, search results, no results, loading, rate-limited and unavailable; detail populated, gone, loading, unavailable, rate-limited, no coordinates and map unavailable. Unavailable has retry; gone has a Gallery link. Search announces result-count changes politely and debounces announcements, not input. Use one main landmark, a logical heading hierarchy, labelled search/map controls, WCAG 2.2 AA focus/contrast and usable touch targets. Keep active rows clear of sticky chrome; clear-search restores focus to the input. An isolated map error boundary retains the itinerary. Preserve focus outside the map. If the focused map control is removed by failure, focus the selected itinerary row when it exists, otherwise the named map fallback region with `tabIndex=-1`; test both paths so focus never silently falls to the document body.
