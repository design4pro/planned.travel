## Method and fidelity

Two ephemeral listeners bind only `127.0.0.1`; one serves the fixture and its own `/ingest`, the
other only receives owned cross-origin traffic. Each phase accepts at most 2000 total requests;
bodies are streamed into a hash, discarded, and capped at 140000 bytes. Only a bounded envelope
header is parsed for identity. The endpoint checks method/origin and returns 204 after 150ms,
exposing the SDK response/backoff headers. There is no proxy or external delivery. Every context
blocks non-owned destinations before navigation; no external requests were attempted.
No customer data, auth, payloads, traces, HARs, screenshots or storage states were retained.

The installed **real `makeFetchTransport`** receives an observer around the native browser fetch.
The observer calls fetch exactly once through `Reflect.apply` with its original receiver and exact
argument objects and returns the exact original promise. Side handlers record metadata only.
It records the actual SDK-serialized body, not an approximation of an event. SHA-256 is asynchronous,
so observation does not await the digest before dispatch. SDK transport, serialization, response
headers, backoff, buffer, sampling and production configuration are not overridden. These are
synthetic transaction envelopes sent directly through the public transport, not full SDK init,
automatic pageload transactions, replay, v2 spans or real Sentry ingestion.

Focused tests pass **4/4**: exact receiver/options/promise/one invocation; UTF-8 sizes and body digest;
rejected native promise and diagnostic binding failure; identity/digest classification and old-document
uncertainty; real installed SDK response metadata, rate-limit backoff, overflow and drain behavior.
The response/backoff/buffer test uses controlled fetch promises, separately from native-browser trials.

The unchanged `watchConsole()` attaches before the first navigation, and remains active through
replacement. Fatal console messages are retained below without suppression. Each trial has a fresh
context and transport. A 150ms endpoint response delay makes overlap meaningful. Early replacement
starts after native attempts; settled replacement waits for each selected envelope's own SDK success
or rejection. Provisional replacement holds its response for 600ms while an old-document timer sends
after 100ms. The original 80 provisional timestamp comparisons could read a previous trial request; their timing certification is superseded by the token-correlated recovery below. Historical receipt/response counts remain observations, not independently certified lifecycle conditions.
Snapshots were taken before navigation; provisional snapshots precede the timer. **All 240 old-document
terminal diagnostic states are unknown** after replacement. A successor's state is never consulted.

All 264 attempts have envelope IDs, body byte/character counts, sequence numbers, keepalive flags
and SHA-256. A receipt requires ID **and** digest **and** bytes; another envelope's response cannot
satisfy a match. Server `finished` is distinct from browser/SDK response. Receipt window ends 220ms
after navigation completion; absence means no matching receipt in this bounded window, not a
universal loss assertion. Of 199 matched receipts, 168 completed their planned 204 response; 31 early ASCII responses
never emitted server `finish` after replacement (16 Chromium, 15 WebKit). Receipt does not imply
response completion.

## Architecture decision and remaining proof

**No verified narrow repair.** Same-origin routing alone fails the same WebKit provisional ASCII
cases, and it cannot remove the native keepalive byte quota. A character-versus-byte heuristic is
observable, but replacing the heuristic or disabling keepalive has not been tested as a safe repair
for lifecycle delivery. The reduced transport-only results do not verify a production correction.
No runtime, ingestion route, privacy, console policy, CI, dependency or GitHub change is included.

A future reviewed route design still needs a concrete reliability mechanism for oversized sends,
identity-correlated responses under document replacement, tenancy/authentication/rate limits, privacy
and scrubber preservation, real ingestion compatibility, full-app regressions and browser coverage.
Same-origin successes are evidence for that review, not permission to deploy a route. No human-only
prerequisite is invented: code/design investigation and a passing contract-preserving regression
remain the next proof.

Only the four focused tests and experiment assertions were run for these new diagnostic files;
full application validation/build was not run. Bootstrap was run as required for the fresh worktree;
it changed no tracked file. An initial notes-to-inbox write failed because the directory did not yet
exist; it was created and the message delivered. Earlier 3-test runs passed before the SDK control
test was added. There were no failed fidelity tests or incomplete browser matrices. An initial results assertion
incorrectly expected every received body to have a finished response; it failed on 31 early
replacement responses and the narrative/assertion was corrected to retain this distinction.
