# Backward compatibility

What this repository treats as a protected contract surface, what counts as a breaking change to
each, and the path a breaking change must take. Review skills (`om-code-review`,
`om-auto-review-pr`) check diffs against this file; implementation skills (`om-fix`,
`om-auto-create-pr`, `om-auto-implement-spec`) warn when a change is not compliant with it.

planned.travel is a multi-tenant SaaS deployed continuously to Cloudflare Workers from `develop`
(staging) and `main` (production). There is no versioned public API and no external SDK, so most
surfaces are protected against **the running deployment**, not against third parties: a Worker
that is live while the database is migrated, a browser tab that loaded the previous bundle, a
share link a stranger bookmarked, an email a traveller will open next week.

## Protected surfaces

### 1. D1 schema and migrations (`src/server/db/schema.ts`, `drizzle/`)

Additive only. A migration runs before the new Worker is deployed, so the previous Worker must keep
working against the new schema.

- **Breaking**: dropping or renaming a table or column, tightening a `NOT NULL` or `CHECK` on a
  column the previous Worker writes, changing a column type, removing an index the previous Worker's
  query plans depend on.
- **Required path**: expand-and-contract across at least two deployments. Add the new column or
  table; ship code that reads both and writes the new shape; backfill; then remove the old shape in
  a later PR once nothing reads it. A migration is only ever generated by `pnpm db:generate`, never
  hand-edited; a reviewer treats a hand-written `drizzle/*.sql` as a blocker.
- Tenant scoping is part of the contract: every tenant table keeps its `organization_id` and every
  query passes through the tenant-scoped base repository (docs/SPEC.md §5, §6).

### 2. Server-function inputs and outputs (`src/server/fns/`)

Server functions are called by the client bundle. During a deployment, a browser that loaded the
previous bundle calls the new Worker for as long as the tab stays open.

- **Breaking**: removing a server function, removing or renaming an input field the previous
  client sends, making an optional input required, removing or renaming a field of the returned
  shape, changing the meaning of an existing field.
- **Required path**: keep the old field accepted (Zod `.optional()`) and the old return field
  populated for one release; land the client change; remove in a follow-up PR. Adding optional
  inputs or new return fields is not breaking. Every input is validated with Zod (docs/SPEC.md §6).

### 3. Session-less reads (`src/server/public/`)

Share links and other token-resolved public reads are bookmarked and embedded outside the product.

- **Breaking**: removing a projection, removing a field from a projection, changing the token
  format or the URL a share record resolves to.
- **Required path**: projections only grow. A field is removed only after a deprecation note in
  the PR and confirmation that no template or client reads it. Adding a field to a projection is a
  security review, not a compatibility one: every field is an explicit whitelist entry of what a
  stranger may see.

### 4. Route paths (`src/routes/`)

Paths under `src/routes/_app`, `src/routes/(auth)`, `src/routes/legal`, `/pricing` and the
`src/routes/api/*` handlers are linked from emails, from the marketing site, from OAuth and billing
providers, and from bookmarks.

- **Breaking**: renaming or removing a route file, changing a path parameter's name or format,
  changing an `api/*` request or response shape, changing the webhook paths registered with Polar
  or the auth callback paths registered with Better Auth.
- **Required path**: keep the old path as a redirect to the new one for at least one release, or
  keep the old handler answering. `src/routeTree.gen.ts` is regenerated with `pnpm generate-routes`,
  never edited.

### 5. Locale catalogue (`src/lib/i18n/messages/`)

The 23 locales are one contract: every key exists in every locale (docs/SPEC.md §9).

- **Breaking**: adding a key to `en` without the other locales, removing a key that any component
  still reads, renaming a key, changing an interpolation placeholder's name or a plural form set.
- **Required path**: a new or renamed key lands in all locales in the same PR (the `i18n-messages`
  skill; the parity test enforces it). A removed key is removed everywhere in the same PR and only
  after its last reader is gone.

### 6. Persisted and queued shapes

- **Queue envelopes** (`src/server/queue/`): a message enqueued by the previous Worker may be
  consumed by the new one. Handlers keep accepting the previous envelope version; new fields are
  optional; a removed field is read as absent, not as an error.
- **Durable Object state** (`src/server/do/`): stored state may predate the new code. Readers
  tolerate the previous shape; migrations happen on read.
- **Trip-room socket frames** (`ServerMessage` and `ClientMessage` in `src/server/do/protocol.ts`):
  a tab that loaded the previous bundle keeps its socket open across a deploy. A change to a
  frame's shape (removing or renaming a field, changing a type, tightening or nulling a field)
  either bumps `TRIP_ROOM_PROTOCOL_VERSION`, which takes an old client offline through the existing
  `protocol-mismatch` error, or lands in two deploys: first a client that tolerates both shapes
  (`serverMessageSchema` drops a frame it does not understand), then the server change. Adding an
  optional field is not breaking.
- **Email templates** (`src/server/email/`): a rendered email is immutable once sent, but the
  message union in `src/server/auth/email.ts` is shared with the queue, so a variant is removed
  only after the queue is drained of it.
- **`user_settings` and `organization_settings` values** (locale, theme, units): stored strings are
  a contract with every row already in D1. A removed or renamed value needs a migration that
  rewrites existing rows.

### 7. Configuration and secrets

- **`wrangler.jsonc` bindings**: renaming a binding or a secret name breaks the deployed Worker
  until the secret is re-set; the PR body must list the operator step and docs/DEPLOY.md must be
  updated in the same PR.
- **`.dev.vars.example`**: a new required variable is added to the example
  file and to `scripts/worktree/bootstrap.sh` in the same PR, or every fresh checkout answers 500.
- **Dependencies**: the stack is pinned (docs/SPEC.md §3). Adding, removing or upgrading a
  dependency is never part of a feature PR; Dependabot PRs and explicit maintenance PRs are the only
  path.

### 8. Agent pipeline contract

- **`.ai/agentic.config.json`, `.ai/trackers/github.md`, `.ai/browsers/playwright.md`,
  `SDLC.md`, this file and `CODE_REVIEW.md`** are read by every `om-*` skill at run time. A change
  to the label taxonomy, the validation commands or a tracker operation changes the behaviour of
  every automated run; it is made by a human, in its own PR, with `SDLC.md` and the config updated
  together.
- **Labels** in the taxonomy are never deleted, renamed or recoloured by a skill.

## Not protected

- Internal module boundaries inside `src/server`, `src/lib` and `src/components` (other than the
  layering contract in CODE_REVIEW.md). Refactor freely with tests.
- Test helpers, seed data (`scripts/seed/`) and e2e fixtures.
- Marketing copy and design tokens; a visual change is a QA question (`needs-qa`), not a
  compatibility one.

## How to record an exception

When a breaking change is unavoidable, the PR body carries a **Compatibility** section naming the
surface, the breaking change, the deployment sequence, and the follow-up PR that completes the
contraction. The reviewer labels the PR `risk-high` and `needs-qa`.
